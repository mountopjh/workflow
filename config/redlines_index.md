# 工程红线编号速查（AI 按编号查询）

> 执行者 与 审计员 仅按工单 §4 引用的编号查这个表。完整定义在 `redlines.toml`。

| 编号 | 标题 | 一句话核心 |
|---|---|---|
| R1 | 流式/分批 | 大数据集禁一次性全量加载，必须分批或流式 |
| R2 | 资源显式释放 | 文件/连接/大内存必须 try/finally / using / defer 释放 |
| R3 | 跨边界容错 | I/O、网络、子进程必须错误处理，日志带上下文 |
| R4 | 依赖锁版本 | 必须有 lockfile，禁全局污染安装 |
| R5 | 文件行数上限 | 默认 300 行；按语言可调（详见 redlines.toml） |
| R6 | 命名语义化 | 禁 utils.* / helper.* / tmp.* / common.* |
| R7 | 自动化测试 | 必有一键可跑的测试入口；禁手测交卷 |
| R8 | 可观测性 | 关键路径有日志，错误含上下文，禁空 catch |
| R9 | 配置双层隔离 | 系统级与业务级配置物理分文件，禁反写系统侧 |
| R10 | 依赖申报 | 新增依赖必须工单 #NewDep 声明 |

## 工单引用方式

规划师 在 `CURRENT_TASK.md` §4 写：
```
- 适用红线：R1, R3, R7
```

执行者 在 `EXECUTOR_OUTPUT.md` §3 必须**逐条**给出落实情况：
```
- [ ] R1: <证据>
- [ ] R3: <证据>
- [ ] R7: <证据>
```

审计员 在 `REVIEW_REPORT_v[n].md` §2 必须**逐条**核查并给出真实源码取证。
